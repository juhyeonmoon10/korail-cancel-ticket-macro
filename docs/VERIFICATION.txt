코레일 한 장 도우미 PC — 공개 배포 검증 요약
기준: 2026-10-23 KST / v0.11.2 개발 소스 (배포 실험판 v0.11.1, 안정판 v0.9.0)

v0.11.2 — 백그라운드 기본 실행 / EXE 실행 검증 보류
- 일반 실행 시 '백그라운드 실행 (기본)'을 켠 상태로 시작함. 체크 변경 이벤트를
  연결하기 전에 모델과 체크 상태를 함께 초기화하며 수동 진단은 계속 비활성화함.
- 다른 앱의 마우스·키보드 입력은 도우미 실행을 중단하지 않는 페이지 입력을 사용함.
  Windows 커서를 이동하거나 외부 앱에 키를 보내지 않음. 체크를 해제하면 기존
  실제 커서 모드이며, 실행 중 모드를 바꾸면 중지 후 다시 시작해야 함.
- Windows 키·Win+Tab·Win+숫자·Alt+Shift+Tab과 일치하는 키 해제를 추적해
  창 전환 시 잘못 중지되는 경우를 수정함. 일반 Tab·Ctrl·문자 입력과 도우미 직접
  조작은 계속 감지하며 F8은 앱 전환 상태와 무관하게 중지함.
- 관련 입력 분류 검사 576개 통과. 실제 키 입력 없이 이벤트 순서를 적용한 순수 검사임.
  설정/Telegram 모의 검사 74개와 알림 전달 검사 31개 통과. 전체 C# 검사는
  PowerShell 실행 도구의 인자/출력 인코딩 오류로 끝까지 완료하지 못함.
- 기본 체크 상태·수동 진단과 실제 호스트의 반복 페이지 클릭/스크롤 검사를 추가함.
  실제 입력 감시 후크를 잠시 사용하는 로컬 문서 검사이며 Windows 입력을 만들지 않음.
  이 새 EXE 검사는 아래 실행 차단으로 수행하지 못함.
- C# EXE 컴파일 성공. 실행 검사 시작 시 Windows 애플리케이션 제어 정책이 차단함.
  Code Integrity 이벤트 3033/3077에서 서명 수준 요구 미충족을 확인함.
  보안 정책을 변경하거나 우회하지 않음. 후속 테스트 문구 수정도 컴파일만 확인함.
- 새 EXE 릴리스는 게시하지 않음. 소스만 업데이트하며 다운로드는 v0.11.1을 유지함.
  v0.11.1에서는 상단 '동시 작업 (실험)'을 직접 켜야 다른 앱과 함께 사용할 수 있음.
- 최소화·잠금·절전·차단 안내와 도우미 직접 조작 시 중지 조건은 유지함.
  완전히 가려진 창, 실제 코레일 조회/예약, Telegram 수신과 장시간 운영은 미검증임.
  실제 예약이나 결제는 수행하지 않음.

v0.11.1 — 기본 모드의 점진적인 커서 이동
- 이전 NativeMouseInput은 절대 좌표 이동 1개와 클릭/스크롤을 한 번에 전달했음.
  이제 클릭·스크롤 전에 약 0.18~0.75초 동안 곡선 경로를 따라 이동함.
  거리와 난수에 따라 이동 시간과 곡률이 달라지며 시작·도착 지점은 고정함.
  UI 스레드를 막지 않고 약 16ms마다 경과 시간을 기준으로 위치를 계산함.
- 조회·더보기·좌석·예매·다음 여정 입력의 클릭은 이동 후 기존 화면 검증을 거침.
  예약 완료 안내 스크롤도 이동 후 안내 내용과 기존 30초 확인 기한을 재검증함.
  예약 제출 기록과 조회 시도 횟수는 이동과 최종 화면 검사 뒤에 기록함.
- F8·직접 클릭·키 입력·창 전환·창/모니터 이동·화면 전환을 매 이동 단계에 확인함.
  이동 도중의 직접 마우스 이동은 중지하지만 대기 중 단순 이동은 계속 허용함.
  250ms를 넘게 UI가 지연되면 입력을 중지하며 마지막 좌표로 순간이동하지 않음.
  실패 시 클릭·재시도·원래 위치 복원을 하지 않음. Windows 입력 출처 표시는 유지함.
- 동시 작업 모드는 기존처럼 WebView에만 입력하며 Windows 커서를 움직이지 않음.
- C# 총 1,155개 통과: 새 경로 검사 313개, 실행 순서/중단 검사 42개 포함.
  화면 경계·음수 좌표·끝점·진행 연속성·경로 변화·중도 취소·전달 실패·시계 오류를 검사함.
  새 이동 검사는 순수 경로와 가상 시간/전달 함수를 사용하며 실제 후크나 커서를 조작하지 않음.
- 최종 EXE의 로컬 WebView 및 호스트 검사 270개 통과 (WebView2 155.0.4283.62).
  이 모의 실행은 Windows 커서를 움직이지 않으므로 실제 네이티브 이동 검증과 구분함.
- JavaScript는 변경하지 않음. 이전 193개 검사 결과를 참고하며 이번에는 재실행하지 않음.
- 실제 Windows 커서 이동부터 코레일 예약·Telegram 수신까지의 전체 흐름과
  자동화 감지 회피 효과는 검증하지 않음. 결제와 실제 예약은 수행하지 않음.

v0.11.0 — 무한 재조회와 여러 열차 완료 조건
- '횟수 제한 없이 반복' 옵션을 추가함. 켜면 비활성 횟수 입력을 무시하고,
  예매 모드는 선택한 완료 조건까지, 조회만 모드는 사용자가 중지할 때까지 반복함.
  오류·차단·인증·F8·기존 요청의 30초 결과 확인 기한은 유지함.
- 메인 화면 하단에 누적 추가 조회 시도 횟수를 별도로 표시함. 초기 조회·더보기는
  제외하며 입력 전달 직전 기록하므로 실제 전달에 실패한 시도가 포함될 수 있음.
  64비트 정수를 사용하며 일시정지·중지 뒤에도 마지막 횟수를 표시함.
- 재조회까지 남은 시간은 5.00초·1.23초·0.00초처럼 두 자리 소수로 표시함.
  표시 전용 타이머만 50ms이며 기존 WebView 읽기·입력 루프 주기는 변경하지 않음.
- 여러 열차는 '하나라도 예약되면 종료'(기본) 또는 '모두 예약하면 종료'를 선택함.
  모두 모드는 실제 완료가 확인된 대상의 기록을 저장하고, 알림 처리 후 남은 대상만
  다시 조회함. 한 열차당 총 1명·예약 1건이며 결제는 진행하지 않음.
- 현재 선택의 모두 모드는 예약 관리에 그 작업을 추가하지만 기존 대기 항목은
  함께 실행하지 않음. 진행 중단·앱 재시작 뒤에도 완료 기록과 조회 횟수를 유지함.
  유한 횟수는 한 항목 전체의 예산이며 부분 성공으로 초기화하지 않음.
- JavaScript 193개, C# 800개 통과. C#에는 새 옵션 84개 및 예약 순서 88개
  검사가 포함됨. Any/All 기본값, 무한 입력, 완료 대상 제외·중복 완료·재시작·
  전체 완료·다른 대기 작업 보존·누적 횟수 저장을 검사함.
- 최종 EXE의 WebView·호스트 검사 270개 통과 (WebView2 155.0.4283.62).
  무한 상태에서 Int32 최대값을 넘는 횟수·결과 갱신 후 다음 대기·30초 기한 유지,
  일시정지·종료 후 횟수 보존, 0.00초·1.23초·5.00초 표시를 검사함.
  모두 예약의 부분 완료·남은 후보 재개·오래된 완료 응답 거절·전체 완료와
  기존 대기 항목 보존을 로컬 호스트에서 확인함.
- 최종 EXE의 새 설정창·기본 및 최소 창 크기를 이미지로 확인함.
  공개 화면 자산 13개가 소스와 일치함을 확인함.
- 실제 코레일에서 여러 열차 연속 예약·무한 반복·Telegram 수신과 장시간 운영은
  검증하지 않음. 모두 예약의 호스트 검사는 합성 완료 기록을 사용하는 로컬 검사임.
  내장 마우스 연습의 다중 후보 '모두'는 지원하지 않으며 명시적으로 시작을 거절함.

v0.10.0 — 동시 작업 입력 모드
- 상단의 '동시 작업 (실험)'을 켜면 WebView2의 페이지 입력 기능으로 클릭·스크롤·
  역 이름 입력을 전달함. Windows 커서를 움직이거나 다른 앱의 포커스를 가져오지 않음.
  DOM click이나 비공개 예약 API를 사용하지 않으며 실패 시 Windows 입력으로 재시도하지 않음.
- 조회, 더보기, 좌석·안내·예매 선택과 예약 순서의 다음 날짜·구간 입력에 연결함.
  기본 마우스 방식은 유지하며 동시 작업은 매 실행 시 사용자가 직접 켜야 함.
  모드를 바꾸면 실행 중인 작업을 중지함.
- 다른 앱의 마우스·키보드 입력과 Alt+Tab 전환은 동시 작업을 중지하지 않음.
  도우미를 직접 조작하면 기존 일시정지·중지 정책을 적용하며 F8은 어디서나 중지함.
- 기존 중복 예약 방지, 예매 요청 전 기록, 차단 감지와 결과 불명 시 중지를 유지함.
  허용된 정차 Alert 외의 안내는 중지 후 '안내 확인'으로 사용자가 직접 확인함.
- 최소화·화면 잠금·절전 상태에서는 실행하지 않음. 다른 창에 완전히 가려지면
  WebView가 멈추거나 느려질 수 있으므로 일부가 보이도록 두거나 다른 모니터에 둬야 함.
- C# 13개 검사 실행 파일에서 750개 통과. 입력 감시 분류 127개와 페이지 입력
  전달 84개를 포함하며, 분류 검사는 실제 후크를 동작시키지 않는 순수 함수 검사임.
- 최종 EXE의 로컬 WebView·호스트 검사 247개 통과 (WebView2 155.0.4283.62).
  실제 WebView 입력 18개 검사에서 클릭·한글 입력·스크롤, 중지 후 입력 차단,
  Windows 커서 위치와 활성 창 불변을 확인함. 외부 앱을 사용하며 실제 코레일의
  전체 예약 흐름을 동시에 실행한 검사는 아님.
- 기존 예약 순서 재개 회귀 검사와 기본·최소 창 크기에서 실행·동시 작업·안내
  버튼의 배치를 검사함. README 화면은 개인정보 없는 로컬 안내 화면임.
- 배포 EXE의 공개 화면 자산 13개가 소스와 일치함을 확인함.
- JavaScript 로직은 변경하지 않음. 기존 0.9.1의 193개 검사 결과를 참고함.
- 실제 코레일에서 동시 작업 모드의 조회·예약·Telegram 수신과 장시간 운영은
  검증하지 않음. 실제 사이트 호환성을 보장하지 않는 실험 버전임.

v0.9.1 당시 검사 이력 — 배포 EXE 미공개
- JavaScript 검사 193개 통과. 그중 다음 여정 조회 분석기 검사 30개 통과.
- 작은 창에서 공식 시간 이동 화살표가 없거나 숨겨졌으면 30초 동안 기다리는 대신
  창 확대와 예약 관리에서 재시작하는 방법을 안내함. 보이는 시간 선택은 유지함.
- 예약 순서의 후보가 더보기 아래에 있어 화면 선택 복원이 끝나지 않았어도,
  일시정지 후 저장된 후보와 시작 시 확정한 실제 조회 조건을 검증해 재개하도록 수정함.
  일반 예약의 확인란 검사, 날짜·구간·시각·후보 순서 변경과 기존 예약 시도 거절은 유지함.
- 이에 대한 WebView 회귀 검사 15개와 준비 검증 5개를 추가했지만 실행하지 못함.
- 0.9.1 EXE 컴파일 성공. 내장 모의 검사 실행 시 Windows의
  '애플리케이션 제어 정책에서 이 파일을 차단했습니다' 오류로 시작하지 못함.
- C# 전체 검사 역시 실행 환경 오류로 완료하지 못함. 일부 출력만으로 통과 처리하지 않음.
- 실제 테스트 준비 중 0.9.0 EXE 프로세스는 실행됐지만, 화면 조작 도구가 해당 창을
  찾지 못해 실제 예약·Telegram 전송·연속 녹화는 시작하지 못함. 결제하지 않음.
- 새 EXE 실행 검증이 끝나지 않아 공개 릴리스는 기존 v0.9.0을 유지함.

위의 30~300초·1~20회·최대 10분 설명은 해당 이전 버전의 검사 이력임.
현재도 조회·더보기 요청의 결과 확인 기한은 30초이며 요청 중 중복 조회를 보내지 않음.

예약 완료 알림은 미결제 예약 확인이며 결제 완료를 뜻하지 않음.
미결제 예약은 공식 화면의 결제기한이 지나면 취소될 수 있음.
인증·접근 제한·알 수 없는 안내에서는 자동 동작을 중지함.
서명되지 않은 EXE이므로 Windows에서 실행을 차단할 수 있으며,
다른 PC나 다른 버전의 실행 결과로 현재 환경의 실행 허용을 보장하지 않음.

검사 방법
소스 루트에서 ./run-mock-tests.ps1로 C# 검사를 수행함.
이 명령에는 짧은 Windows 절전 방지 요청·해제 검사가 포함되며 전원 설정을 바꾸지 않음.
JavaScript 검사는 npm install --ignore-scripts 후 npm test로 수행함.
로컬 검사는 실제 예약·Telegram 수신 검사를 대체하지 않음.
