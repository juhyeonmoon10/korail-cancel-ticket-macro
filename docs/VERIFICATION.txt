코레일 한 장 도우미 PC — 공개 배포 검증 요약
기준: 2026-10-23 KST / v0.10.0 실험 버전 (안정 배포본은 v0.9.0)

v0.10.0 — 동시 작업 입력 모드
- 상단의 '동시 작업 (실험)'을 켜면 WebView2의 페이지 입력 기능으로 클릭·스크롤·
  역 이름 입력을 전달함. Windows 커서를 움직이거나 다른 앱의 포커스를 가져오지 않음.
  DOM click이나 비공개 예약 API를 사용하지 않으며 실패 시 Windows 입력으로 재시도하지 않음.
- 조회, 더보기, 좌석·안내·예매 선택과 예약 순서의 다음 날짜·구간 입력에 연결함.
  기본 마우스 방식은 유지하며 동시 작업은 매 실행 시 사용자가 직접 켜야 함.
  모드를 바꾸면 실행 중인 작업을 중지함.
- 다른 앱의 마우스·키보드 입력과 Alt+Tab 전환은 동시 작업을 중지하지 않음.
  도우미를 직접 조작하면 기존 일시정지·중지 정책을 적용하며 F8은 어디서나 중지함.
- 기존 중복 예약 방지, 예매 요청 전 기록, 차단 감지와 결과 불명 시 중지를 유지함.
  허용된 정차 Alert 외의 안내는 중지 후 '안내 확인'으로 사용자가 직접 확인함.
- 최소화·화면 잠금·절전 상태에서는 실행하지 않음. 다른 창에 완전히 가려지면
  WebView가 멈추거나 느려질 수 있으므로 일부가 보이도록 두거나 다른 모니터에 둬야 함.
- C# 13개 검사 실행 파일에서 750개 통과. 입력 감시 분류 127개와 페이지 입력
  전달 84개를 포함하며, 분류 검사는 실제 후크를 동작시키지 않는 순수 함수 검사임.
- 최종 EXE의 로컬 WebView·호스트 검사 247개 통과 (WebView2 155.0.4283.62).
  실제 WebView 입력 18개 검사에서 클릭·한글 입력·스크롤, 중지 후 입력 차단,
  Windows 커서 위치와 활성 창 불변을 확인함. 외부 앱을 사용하며 실제 코레일의
  전체 예약 흐름을 동시에 실행한 검사는 아님.
- 기존 예약 순서 재개 회귀 검사와 기본·최소 창 크기에서 실행·동시 작업·안내
  버튼의 배치를 검사함. README 화면은 개인정보 없는 로컬 안내 화면임.
- 배포 EXE의 공개 화면 자산 13개가 소스와 일치함을 확인함.
- JavaScript 로직은 변경하지 않음. 기존 0.9.1의 193개 검사 결과를 참고함.
- 실제 코레일에서 동시 작업 모드의 조회·예약·Telegram 수신과 장시간 운영은
  검증하지 않음. 실제 사이트 호환성을 보장하지 않는 실험 버전임.

v0.9.1 당시 검사 이력 — 배포 EXE 미공개
- JavaScript 검사 193개 통과. 그중 다음 여정 조회 분석기 검사 30개 통과.
- 작은 창에서 공식 시간 이동 화살표가 없거나 숨겨졌으면 30초 동안 기다리는 대신
  창 확대와 예약 관리에서 재시작하는 방법을 안내함. 보이는 시간 선택은 유지함.
- 예약 순서의 후보가 더보기 아래에 있어 화면 선택 복원이 끝나지 않았어도,
  일시정지 후 저장된 후보와 시작 시 확정한 실제 조회 조건을 검증해 재개하도록 수정함.
  일반 예약의 확인란 검사, 날짜·구간·시각·후보 순서 변경과 기존 예약 시도 거절은 유지함.
- 이에 대한 WebView 회귀 검사 15개와 준비 검증 5개를 추가했지만 실행하지 못함.
- 0.9.1 EXE 컴파일 성공. 내장 모의 검사 실행 시 Windows의
  '애플리케이션 제어 정책에서 이 파일을 차단했습니다' 오류로 시작하지 못함.
- C# 전체 검사 역시 실행 환경 오류로 완료하지 못함. 일부 출력만으로 통과 처리하지 않음.
- 실제 테스트 준비 중 0.9.0 EXE 프로세스는 실행됐지만, 화면 조작 도구가 해당 창을
  찾지 못해 실제 예약·Telegram 전송·연속 녹화는 시작하지 못함. 결제하지 않음.
- 새 EXE 실행 검증이 끝나지 않아 공개 릴리스는 기존 v0.9.0을 유지함.

v0.9.0

- 배포 EXE를 직접 실행해 로컬 WebView·호스트 모의 검사 207개 통과.

- 같은 조회 조건·정확한 열차 식별·시각·등급일 때 선택을 복원함.
  페이지·설정 변경 중 선택 유지, 확인란 보존, 명시적 초기화,

- 예약 순서 20건, 항목당 후보 20편의 저장·순서 변경·재시작 복구를 검사함.
  한 후보의 예약 완료 근거가 확인된 경우에만 해당 항목을 완료함.
  불명확한 결과, 중복 완료, 이전 알림의 늦은 응답, 최소화·중지 뒤
  다음 항목이 시작되지 않는 호스트 상태 전환을 모의 검사함.
- 다음 조회는 공식 화면의 역 검색·달력·시간·열차 분류·조회 버튼을 판별함.
  JavaScript는 읽기와 좌표 계획만 반환하며, 입력은 기존 Windows 마우스·키보드 경로임.
  조회 요청 후 실제 탐색 또는 결과 목록 변경과 750ms 안정화를 요구함.
  현재 시각 때문에 조회 시작 시간을 조정할 때도 첫 후보 출발 시간을 넘기지 않음.
- 배포 EXE의 공개 화면 자산 13개가 소스와 일치함을 확인함.
- 실제 코레일에서 다음 여정 입력·연속 예약·Telegram 수신과 밤샘 실행은
  이 버전에서 검증하지 않음. 모의 검사가 실제 서비스 성공을 보장하지 않음.

v0.8.4 검사 이력
- C# 검사 447개 통과. 대기 범위 56개와 입력 검증 59개를 포함함.
- 배포 EXE를 직접 실행해 내장 WebView 모의 검사 186개 통과.
  실제 설정창의 5초·9999999회 입력 유지, 5초·999999회 수락,
  잘못된 값의 오류 표시와 시작 차단을 확인하고 설정창 이미지를 확인함.
- 로컬 검사에서 조회 횟수를 20회와 999998회, 경과 시간을 11분으로 설정해
  임의 중지 없이 대기·재개 검증을 유지하는지 확인함. 실제 11분 반복 조회가 아님.
  최대 정수 횟수 경계에서 넘침 없이 완료하며, 요청별 30초 기한이 유지되는지 검사함.
  이 검사는 실제 마우스 입력·코레일 요청·Telegram 전송을 발생시키지 않음.
- 배포 EXE에 포함된 공개 화면 자산 12개가 소스와 같은지 확인함.
  JavaScript 코드는 변경하지 않았으며 아래 v0.8.3의 150개 검사 결과를 참고함.
- 조회 간격과 최대 추가 조회 횟수를 텍스트 입력칸으로 변경함.
  각각 1~2,147,483,647의 정수를 허용하며 5초·999999회·9999999회를 그대로 사용함.
- 빈칸·소수·음수·범위 밖 입력은 오류를 표시하고 시작을 막음.
  입력값을 최소 30초·최대 20회로 몰래 보정하던 동작을 제거함.
- 별도 10분 총 실행 제한을 제거함. 설정한 추가 조회 횟수는 유지함.
- 랜덤 지연은 0~100%, 범위는 간격 × (1 ± 비율)임.
  실제 대기는 최소 1초로 0초 대기를 방지하며 기존 300초 상한을 제거함.
  5초·0%는 5초, 5초·20%는 4~6초 범위임.
- 첫 재조회 전과 이전 요청의 결과 확인 완료 후 다음 재조회 전에 대기를 정함.
  조회 버튼의 클릭 간격을 정확히 고정하는 방식이 아니며 요청 중 중복 조회를 보내지 않음.
- 조회·더보기 요청의 30초 결과 확인 기한, 차단·인증 안내에서 중지와 F8을 유지함.
  후보 최대 20편, 더보기 최대 30회·결과 2,000행 제한도 유지함.
- 이 버전의 실제 코레일 더보기 클릭·조회·예약과 Telegram 예약 완료 알림,
  실제 밤샘 실행은 검증하지 않음.

v0.8.3 검사 이력
- JavaScript 검사 150개와 C# 검사 380개 통과.
- 배포 EXE를 직접 실행해 내장 WebView 모의 검사 159개 통과.
  더보기 이후 열차 읽기, 원래 후보 순서, 목록 추가·중복·교체·무변화,
  일시정지 중 기한 유지와 화면 읽기 도중 30초를 넘긴 결과 거절을 검사함.
- 더보기 검사는 로컬 목록 판정과 대기·완료·재개 검증 경로를 실행했으며,
  실제 마우스 클릭·스크롤 후크나 실제 코레일 요청을 발생시키지 않았음.
- 배포 EXE에 포함된 공개 화면 자산 12개가 소스와 같은지 확인함.
- 열차 목록 읽기를 누르면 더보기 끝까지 마우스로 펼친 뒤 열차를 다시 읽도록 변경함.
  완료 후 선택 패널을 다시 펼침. JavaScript는 목록 읽기 요청과 화면 판정만 수행하며
  공식 화면의 더보기 클릭·스크롤은 마우스 입력 기능에서 수행함.
- 예약을 포함한 재조회 후 선택 후보가 누락되면 모든 후보를 찾을 때까지 더보기를 누름.
  처음 선택한 후보 순서를 유지하며 조회만 모드는 기존 재조회 흐름을 유지함.
- 더보기 후 기존 목록이 같은 순서로 남고 새 행이 추가된 상태가 1초간 유지되는지 확인함.
  30초간 변화 없음, 결과 교체·중복·차단에서는 추가 클릭 없이 중지하도록 구성함.
- 한 번의 목록 펼치기에서 더보기 최대 30회, 결과 최대 2,000행을 허용함.
  더보기 클릭 횟수와 추가 조회 횟수를 별도로 세며 전체 실행 최대 10분은 유지함.
- 더보기 중 일시정지·계속을 지원하며 원래 더보기 클릭의 30초 확인 기한을 연장하지 않음.
- 코레일의 공개 화면 코드에서 더보기 요소의 구조를 확인함. 실제 코레일에서
  이 버전의 더보기 클릭·조회·예약과 Telegram 예약 완료 알림은 검증하지 않음.

- 가격 선택 뒤나 예매 요청 뒤의 클릭·스크롤·키 입력·창 전환·최소화에는
  기존 중지·결과 확인 절차를 유지함.
- F8·모두 중지·차단·페이지 이동·설정 변경·화면 잠금·절전은 완전 중지함.
- 일시정지 중 절전 방지를 해제함. 실행당 최대 10분에 일시정지 시간도 포함하며,
  실제 대기 30~300초·추가 조회 1~20회 제한을 유지함.
- 이미 조회 버튼을 눌렀다면 원래 클릭 시점부터 30초 안에 결과 갱신을 확인해야 함.
  일시정지로 확인 기한을 연장하지 않으며, 초과하면 추가 클릭 없이 중지함.
- 일시정지·중지는 프로그램 동작을 멈추며 실제 예약을 취소하지 않음.
- 이 버전의 실제 코레일 조회·예약과 Telegram 예약 완료 알림은 검증하지 않음.

검증 범위
한 번의 실제 성공이나 이전 버전의 결과가 모든 열차·사이트 변경·PC 환경에서의
성공을 보장하지 않음. 밤샘 운영은 검증하지 않음. 현재 버전은 간격과 추가 조회 횟수에
각각 1~2,147,483,647의 정수를 허용하며 별도 총 실행시간 제한은 없음.
위의 30~300초·1~20회·최대 10분 설명은 해당 이전 버전의 검사 이력임.
현재도 조회·더보기 요청의 결과 확인 기한은 30초이며 요청 중 중복 조회를 보내지 않음.

예약 완료 알림은 미결제 예약 확인이며 결제 완료를 뜻하지 않음.
미결제 예약은 공식 화면의 결제기한이 지나면 취소될 수 있음.
인증·접근 제한·알 수 없는 안내에서는 자동 동작을 중지함.
서명되지 않은 EXE이므로 Windows에서 실행을 차단할 수 있으며,
다른 PC나 다른 버전의 실행 결과로 현재 환경의 실행 허용을 보장하지 않음.

검사 방법
소스 루트에서 ./run-mock-tests.ps1로 C# 검사를 수행함.
이 명령에는 짧은 Windows 절전 방지 요청·해제 검사가 포함되며 전원 설정을 바꾸지 않음.
JavaScript 검사는 npm install --ignore-scripts 후 npm test로 수행함.
로컬 검사는 실제 예약·Telegram 수신 검사를 대체하지 않음.
